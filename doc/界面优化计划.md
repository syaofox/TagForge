# TagForge 界面优化计划

> 状态说明：P0=便利性优先（建议先做）；P1=精致度升级；P2=进阶能力（按需）。
> 每个条目带「状态」列，实施时打勾更新。

---

## 一、问题诊断

### A. 信息架构 —— 左抽屉「一锅端」（最影响便利）
左侧 320px 抽屉一次性堆入：项目管理（新建/删除/列表）、模型配置（预设/BaseURL/模型/Key/测试连接）、提示词预设+文本框+角色名、触发词前缀、并发数、导出。
高频操作（选项目、批量）与低频项（并发数、前缀）混排，超过一屏必须滚动。

### B. 主区域信息密度 —— 无概览、无导航
- 顶部只有项目名 + 上传/批量按钮，无任何统计（已标注/待标注/失败计数）；
- 无搜索、无状态过滤，图片多时难定位；
- 网格一次全量渲染所有 base64 缩略图（无分页/懒加载），图多卡顿。

### C. 反馈与状态缺失
- 网格加载无 loading；空项目/无 API Key/无图片无引导式空态；
- 上传无进度、同名覆盖静默执行；
- 批量只有一条小进度条，无 完成/失败/剩余时间/结果汇总；
- 保存/删除无撤销。

### D. 视觉精致度
- 已标注/待标注卡片外观无区分；
- 深色模式部分控件对比不足；
- 无加载骨架、动效少、图标/排版层级弱；
- 详情大图不能点开放大；
- 系统回退字体，中文观感一般。

### E. 效率细节
- 详情编辑无快捷键；
- 批量前不能「先试生成 1 张」验证提示词/模型；
- 批量结束后失败项无「一键重试失败」；
- Token 统计藏在右下角，存在感低。

## 三、建议实施顺序

1. **P0-1~4**（统计筛选、搜索、分页、空态）：一次重构 `refresh_grid` 为「过滤 + 分页 + 状态」，后续 5、6 复用同一结构；
2. **P0-5、6**（上传、批量）：复用统计条计数逻辑；
3. **P1-7~12**：纯 UI 打磨，风险低，逐个并进；
4. **P2**：挑最痛点（撤销 13、虚拟滚动 16）按需做。

> P0-1~3 是全局最大性价比点。
