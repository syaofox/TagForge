
# 项目需求：TagForge — LoRA 数据集图片打标工具

## 一、项目概述

开发一个名为 **TagForge** 的 Web 端图片打标工具，专门用于 LoRA 模型训练数据集的批量标注。技术核心为 **Python + NiceGUI**，采用 **纯异步并发** 调用大模型 API，**不依赖任何传统数据库**（PostgreSQL/MySQL），所有数据以文件系统 + JSON 方式存储。最终通过 **Docker Compose（最新版 V2，无需声明 version）** 一键部署，仅供单人局域网使用。

---

## 二、技术架构硬性要求（必须遵守）

1. **Web 框架**：仅使用 **NiceGUI (>=2.0.0)**，不拆分前后端。所有 UI 组件用 Python 编写。
2. **异步处理**：所有涉及大模型 API 调用的逻辑必须使用 `async/await`。使用 `asyncio.Semaphore` 控制并发数（默认 5）。UI 必须保持响应，严禁阻塞主线程。
3. **数据存储（零数据库）**：
   - 图片存放在 `datasets/{项目名}/images/`。
   - 标签存放在 `datasets/{项目名}/labels/` 下，与图片同名（扩展名 `.txt`）。
   - 短标签模式：txt 内存放逗号分隔的关键词（如 `1girl, blonde hair, smile`）。
   - 自然语言模式：txt 内存放完整描述句。
   - 项目列表和全局配置（API Key、Base URL、默认 Prompt）存放在 `config/settings.json`。
4. **图片状态判定**：程序启动时扫描 `datasets/` 目录下的子文件夹作为项目列表。若 `labels/` 下存在同名 `.txt` 且内容非空 => 状态为“已标注”；否则为“待标注”。
5. **容器化部署**：提供 `Dockerfile` 和 `docker-compose.yml`（**不包含 version 字段**，仅需一个服务容器，无需 Postgres/Redis 附加容器）。

## 六、并发与防卡死策略（关键）

- 使用 `asyncio.Semaphore(5)` 限制最大并发数。
- 在批量处理的 `for` 循环中，每处理完一张图，必须执行以下操作刷新 UI：
  ```python
  progress.value = (idx + 1) / total
  await asyncio.sleep(0.01)  # 让出事件循环给 NiceGUI
  ```
- 所有异步任务启动前，必须检查当前项目是否为空。
- **批量循环必须作为后台 asyncio 任务运行**（如 `nicegui.background_tasks.create(...)`），而不是写在普通事件处理器里；`progress.value = (idx + 1) / total; await asyncio.sleep(0.01)` 仅在 async 协程内有效。
- **错误分级**：401/403（无效 Key）为致命错误，立即中止整批并提示；429/5xx 为瞬时错误，指数退避重试（最多 3 次）；其余网络异常计入单张“失败”状态。
- **断连保护**：后台任务持续更新 UI 元素时，若用户刷新/关闭页面，更新已断开连接的 client 会抛异常；每次 UI 更新须用 try/except 包裹或先检查任务是否被取消。

### 11.2 实现约定（补充）
- **缩略图缓存**：存 `datasets/.cache/{项目}/`，按 mtime/尺寸校验，生成放 `run.io_bound`（线程池，见第三节说明）；网格可懒加载/分页。

- **删除联动与确认**：删除图片/删除项目均需二次确认；删除图片时同步删除同名 `.txt`。
- **状态持久化**：🔴失败 / 🔵处理中为运行时态，重启后回到 🟡待标注（批量会自动重跑失败图，语义自洽）；如需跨重启保留失败标记，可另写 `status.json`（可选）。

### 11.3 settings.json 建议 schema（首次运行自动创建并填默认值）
```json
{
  "api_key": "",
  "base_url": "https://api.openai.com/v1",
  "model": "gpt-4o-mini",
  "system_prompt": "<短标签默认 prompt>",
  "tag_prefix": "",
  "prefix_mode": "prepend",
  "dark": false,
  "concurrency": 5,
  "last_project": "",
  "prompt_preset": "en_short_default",
  "preset_keys": {
    "OpenCode (Zen/Go)": "<key>",
    "DeepSeek (官方)": "<key>"
  }
}
```
- `mode`: `short`=短标签（逗号分隔） / `natural`=自然语言描述。
- `prefix_mode`: `prepend`=整体前置 / `per_tag`=每个 tag 加前缀。
- `system_prompt`：与当前模式的默认提示词一致时视为「未自定义」，切换打标模式会自动跟随新模式默认；用户修改后即为自定义内容，始终优先于模式默认、不被切换覆盖（`恢复默认`按当前模式重置）。
- `preset_keys`：**模型预设 → API Key** 的映射（明文，仅存于 gitignore 的 `settings.json`）。切换「模型预设」下拉时自动回填对应 Key；在某预设下手动修改 Key 会自动记住到该预设。
- `prompt_preset`（System Prompt 为**下拉框**，含**输出语言**维度，已取代原「打标模式」单选，`mode` 字段已移除）：键形如 `<语言>_<格式>_<目标>`，共 17 项——语言 `en`（英文） / `zh`（中文） × 格式 `short`（短标签） / `natural`（自然语言） × 目标 `default`（通用）/ `character`（角色 LoRA）/ `clothing`（服装 LoRA）/ `style`（风格 LoRA），外加 `custom`=自定义。选择预设自动填充文本框；手动编辑文本框即自动切为 `custom`。
- **训练预设提示词依据**（`character`/`clothing`/`style` 每套均有英文/中文两个输出版本；`short` 输出 danbooru 风格标签或中文关键词，`natural` 输出一句自然语言）：角色——省略固定身份特征（脸/瞳/发/体型，由触发词吸收），保留服装/姿势/表情/镜头/背景/光线且元素顺序一致；服装——服装是主体，具体描述款式/颜色/面料/版型/细节/褶皱，穿者泛化；风格——打「内容」不打「风格」，风格词至多 2-3 个稳定词，禁止 `masterpiece/best_quality/4k` 等质量词。参考：lora-dataset-prep/reference.md（角色公式与 include/omit 表、服装/风格/对象各类型规则）、AnimaLoraStudio training-tips（角色 LoRA 的 caption 删特征靠 trigger 吸收、画风 LoRA 打内容不打风格）。
