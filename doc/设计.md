# TagForge 设计文档（当前实现）

> 本文件描述项目**当前实现**的设计与约定，是后续开发的权威参考。
> 历史：早期为 NiceGUI（2025-08 迁移至 FastAPI/HTMX），**不得再引回 NiceGUI**。

## 一、项目概述

LoRA 数据集图片打标工具：Web 端批量标注，单机 / 局域网单人使用。
技术栈：**Python + FastAPI + Jinja2 + HTMX**，零数据库（文件系统存储），无前端构建步骤。
所有大模型调用为纯异步并发；最终经 Docker Compose 一键部署。

## 二、技术架构

### 1. 模块职责（职责严格分层）

| 模块 | 职责 |
|---|---|
| `app.py` | FastAPI 路由薄层：参数解析 → 调 core → 渲染 partial/JSON/文件/SSE。**不含业务逻辑**。 |
| `core.py` | 纯业务逻辑，0 框架依赖、可单测。常量/预设、配置读写、文件扫描与状态、图片处理、项目 CRUD/导出/上传、批量协程、提示词解析。 |
| `llm_client.py` | OpenAI 兼容大模型异步封装：指数退避重试（最多 3 次）、Token 累计、`FatalAPIError`（401/403 或重试耗尽 → 中止整批）。 |
| `templates/` | Jinja2 服务端渲染：`base.html` 页面外壳 + `partials/` 可独立 swap 的 HTML 片段。 |
| `static/` | `css/tf.css` + `js/app.js` + `vendor/htmx.min.js`（单文件 vendor，无构建）。 |

### 2. 运行时状态

`core.state`（`AppState` dataclass）为模块级单例：单人使用、无会话态，浏览器只是渲染端。承载：配置、项目列表、`current`、`entries`、LLMClient、`batch`（asyncio task）、`abort_batch`、视图状态（`view_filter` / `view_query` / `view_page`）、批量进度 SSE 队列 `batch_queue` 等。
`ImageEntry`：`name / path / status / label`；卡片/详情图走 `/api/image/...` 静态直连，不存 data URL。

### 3. 并发模型

- 所有大模型调用必须 `async/await`；并发用 `asyncio.Semaphore`（默认 5，`settings.concurrency`）。
- 缩略图生成 / 图片编码 / 文件 IO 用 `asyncio.to_thread`，严禁阻塞事件循环。
- 批量任务用 `asyncio.create_task` 启动并存入 `core.state.batch`，`lifespan` shutdown 时取消。
- 服务器不持有 DOM 引用，故不存在 NiceGUI 时代的「element deleted / 断连 client」异常。

## 三、数据约定（零数据库）

- 图片：`datasets/<项目>/images/`；支持扩展名 `jpg/jpeg/png/webp/bmp`（白名单 `core.IMAGE_EXTS`）。
- 标签：`datasets/<项目>/labels/<同名>.txt`；短标签存逗号分隔关键词，自然语言存完整句子。
- 缩略图缓存：`datasets/.cache/<项目>/<同名>.thumb.jpg`，按 mtime/尺寸校验（`core.ensure_thumb_file`）。
- 全局配置：`config/settings.json`（含 API Key，已 gitignore）；导出：`exports/<项目>.zip`（内含 `images/` + `labels/`）。
- 上传同名自动改名 `name (1).ext`（`core.resolve_upload_destination` 提取纯文件名剥离路径组件 + 扩展名白名单校验）。

### 图片状态机

| 状态 | 含义 | 持久性 |
|---|---|---|
| `pending` | 待标注（无 `.txt` 或为空） | 磁盘推导 |
| `tagged` | 已标注（`.txt` 非空） | 磁盘推导 |
| `processing` | 处理中（运行时态） | 重启回 `pending` |
| `failed` | 失败（运行时态） | 重启回 `pending`（批量自动重跑失败图） |

状态徽章文案/颜色：`core.STATUS_TEXT` / `core.STATUS_COLOR`。

## 五、HX-Trigger 事件总线

| 事件 | 触发方 | 前端动作 |
|---|---|---|
| `gridChanged` | 保存/删除图片、再生、试生成（`HX-Trigger`）；上传、批量完成由前端直接 `refreshGrid()` | 刷新 `#grid` 卡片区 |
| `detailReload` | 再生/试生成完成 | 重载详情抽屉 |
| `detailClosed` | 删除图片 | 关闭抽屉 |
| `batchStarted` | `/api/batch/start` / `retry` | 建立 EventSource、显示批量卡 |
| `tokensUpdated` | 批量完成/试生成 | 刷新顶栏 Token |
| `toast` | 任意 API（携带 `{msg, type}`） | app.js 弹提示 |

> 事件监听在 `static/js/app.js` 中统一注册；服务端用 `_toast` / `_trigger` 组装 `HX-Trigger` 头（`app.py`）。

## 六、批量标注与 SSE 协议

`core.run_batch(targets, project, settings, client, progress_cb)` 纯业务协程，UI 无关，进度以回调驱动：

- 事件类型：`mark`（entry 状态变化）、`log`（日志行）、`progress`（`{done,total,ok,fail,elapsed}`）、`done`（`{ok,fail,aborted,...}`）。
- 回调必须非阻塞；`app.py` 的 `_enqueue` 采用**快照式入队**（`Queue(maxsize=1)`，新事件替换旧事件），保证最新事件（含 `done`）不丢。
- 错误分级：401/403（无效 Key）→ `FatalAPIError` 立即中止整批；429/5xx/网络 → 指数退避重试（最多 3 次）后 `FatalAPIError`；其余异常 → 单张 `failed`。
- SSE 端点 `GET /api/batch/events`：循环 `queue.get()`（超时 25s 发 keepalive），`done` 后以哨兵 `None` 结束；无消费者时事件自然丢弃。
- 前端 `EventSource`：`progress` 更新进度条/统计，`log` 追加日志，`done` 后关闭连接并刷新网格与 token。

## 七、提示词预设规范

「提示词预设」下拉为**三维组合：输出语言 × 格式 × 训练目标**，共 17 项（`core.PROMPT_PRESETS`）：
语言 `en`/`zh` × 格式 `short`（短标签）/`natural`（自然语言） × 目标 `default`/`character`/`clothing`/`style` + `custom`。

- 预设文本定义在 `core.DEFAULT_PROMPTS`（通用）与 `core.TRAINING_PROMPTS`（训练场景，每目标 × 格式均有中英两版）。
- 选择预设 → `/api/settings/prompt` 用 `core.resolve_prompt_text` 填充 `system_prompt`；手动编辑文本框即视为「自定义」（前端自动切 `prompt_preset=custom`）。
- **角色名注入**（`settings.character_name`）：仅「角色 LoRA」预设生效，追加“将该名称嵌在人物称谓之后（如「…的女子<角色名>，…」，不置于句首/句尾）”；其余预设不受影响。
- 训练预设规则要点：
  - **角色**：自然语言版句子以镜头开头（「一张…照片，照片中一位…」）、触发词嵌在人物称谓后；发型发色必须描述，其余省略数据集内固定身份特征（脸型/瞳色/肤色/体型，由触发词吸收），保留服装/姿势/表情/镜头距离与角度/背景/光线，元素顺序一致；**可见的临时性特征必须打标**（液体、泪水、脸红、泥污等），头发干湿必须打「湿发/wet hair」，防止被固化为身份特征。
  - **服装**：服装是主体，具体描述款式/颜色/面料/版型/细节/褶皱，穿者泛化。
  - **风格**：打「内容」不打「风格」，风格词至多 2-3 个稳定词，禁质量词（`masterpiece/best_quality/4k`）。
  - 中文自然语言版必须要求「带标点的完整句子、禁止无标点关键词串」，并给固定句式骨架 + 示例。
- 旧配置兼容迁移逻辑在 `core.load_settings`（v1 `mode`/旧键 → 新键推断）。

## 八、settings.json schema

```json
{
  "api_key": "",
  "base_url": "https://api.openai.com/v1",
  "model": "gpt-4o-mini",
  "system_prompt": "<预设填充的提示词>",
  "tag_prefix": "",
  "prefix_mode": "prepend",
  "character_name": "",
  "dark": false,
  "concurrency": 5,
  "last_project": "",
  "prompt_preset": "en_short_default",
  "preset_keys": { "<模型预设名>": "<api key>" }
}
```

- `prefix_mode`：`prepend`=整体前置 / `per_tag`=每个 tag 加前缀（`core.apply_prefix` 会避免重复叠加）。
- `preset_keys`：模型预设 → API Key（明文，仅存于 gitignore 的 settings.json）；切换预设自动回填 Key，改 Key 自动记住到当前预设。
- `system_prompt` 由 `prompt_preset` 驱动；手动编辑自动切 `custom`。
- 模型预设**统一处理**：内置预设定义在 `core.DEFAULT_MODEL_PRESETS`（OpenCode (Zen/Go)、DeepSeek 官方）；用户可新增/覆盖/改名/删除任意预设，持久化在独立的 `config/presets.json`（gitignore）：

  ```json
  {
    "custom_presets": { "<预设名>": {"base_url": "...", "model": "..."} },
    "removed_presets": ["<被删除的内置预设名>"]
  }
  ```

  生效集合 = 内置（剔除 `removed_presets`）+ 自定义覆盖（同名覆盖内置）；`core.get_effective_presets()` 为唯一查询入口。删除内置仅移入删除标记，被自定义覆盖的内置删除后回到默认。预设名校验：非空、≤50 字符。
- 模型名输入为 `input + datalist`：前端在切换预设 / 修改 Base URL / 点「刷新」时 `POST /api/models` 从提供商拉取列表（不缓存）；网关不支持 `/models`（404）时返回空列表，前端提示可手动输入。

## 九、API 兼容边界与 LLMClient 约定

- **仅封装 OpenAI 兼容接口**。兼容性边界：
  - Claude（Anthropic 官方）非 OpenAI 兼容，须经中转站暴露为 OpenAI 兼容端点（预设 `api.anthropic.com/v1` 默认不可直连）；
  - DeepSeek 官方 API 无视觉模型，DeepSeek-VL 须自建 vLLM/SGLang 的 `/v1` 端点；
  - Ollama 的 OpenAI 兼容端口为 `http://<host>:11434/v1`。
- 发送前预处理：原图缩放最大边 1280、JPEG q=80 再转 data URL（`core.encode_for_api`）。
- `AsyncOpenAI` 必须设请求超时（`httpx.Timeout(90, connect=10)`），`max_retries=0`（重试由本类控制）。
- `AsyncOpenAI` 附带 `default_headers`：`x-opencode-session`（每次构建客户端生成的 UUID，OpenCode Go 等网关要求会话标识）与 `User-Agent: tagforge/1.0`；普通 OpenAI 兼容端点会忽略，无副作用。
- `response.usage` 可能为 `None`（Ollama/部分中转站），累加前判空，退化显示 0。
- API Key 为空且非 Ollama 时禁用批量/试生成（`core.client_ready`）。

## 十、前端约定与已知问题

- 局部刷新一律 HTMX + `HX-Trigger`；仅批量进度走 SSE。
- 详情内容每次被 HTMX 替换，事件监听须用**事件委托**（`document.body` 上 `htmx:afterSwap`/click 委托），或 swap 后重挂。
- CSS 中 `[hidden] { display: none !important; }` 守卫**不可删**：防 author 的 display 规则覆盖 `hidden` 属性导致黑屏（lightbox/批量卡等），有回归测试守护。
- 上传用逐文件 `XMLHttpRequest`（有 `upload.onprogress`），拖拽监听在 `#main` 上。
- **路径穿越防护**：`resolve_upload_destination` 先用 `Path(name).name` 提取纯文件名（剥离 `/`、`\`、`..` 等路径组件），防上传文件名写出 `images/` 目录，有回归测试守护。

## 十一、部署与开发

- **Docker**：`Dockerfile`（`python:3.12-slim`，`python -m uvicorn app:app --host 0.0.0.0 --port 8080`，非 root `appuser:1000` + `HEALTHCHECK`）+ `docker-compose.yml`（`name/image/container_name` 固定、`user` 映射、`healthcheck`）；挂载 `./datasets`、`./config`、`./exports`。首次运行前 `mkdir -p datasets config exports` 防 root 权限问题（`user` 已映射为宿主机 UID）。
- **宿主机**：统一 `uv` 管理虚拟环境：
  ```bash
  uv sync                                 # 或：uv venv && uv pip install -r requirements.txt
  source .venv/bin/activate
  uv run python -m uvicorn app:app --host 0.0.0.0 --port 8080
  # 新增依赖：uv add <pkg> 或改 pyproject.toml 后 uv sync；同步导出：uv export --format requirements-txt --no-hashes > requirements.txt
  ```
- 依赖：`pyproject.toml` 为主（`uv sync`/`uv.lock` 已 pin），`requirements.txt` 为 Docker/`pip` 兼容导出（与 `pyproject.toml` 版本一致）。前端仅 vendor 单文件 `htmx.min.js`，不进 pip。
